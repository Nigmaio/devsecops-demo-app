Today’s exercises introduce two important DevSecOps practices:

# Exercise 1: Build and Run a Container
## Goal
Build and run a simple containerised application while practising the core Docker workflow:

Build an image.

Run a container.

Inspect the container.
## Prerequisites

Before you begin, make sure that:

- Docker is installed and running.

- The exercise repository is available locally.

- You have access to a terminal or command prompt.

## Step 1: Clone the Repository 
If you have not cloned the repository yet, run:


  ` git clone "Insert repo url"`
  or
  ` cd "repo folder"`

If the repository is already cloned, navigate to the project folder and pull the latest changes:

`cd "<REPOSITORY_FOLDER>"`

`git pull`

## Step 2: Build the Docker Image
Run the following command from inside the repository folder:

- Build the image:
   `docker build -t hello-app .`

   This command:

- Reads the instructions in the Dockerfile.

- Packages the application and its Python runtime.

- Creates an image named hello-app.

## Step 3: Run the Container
Start a container from the image:
`docker run hello-app`

You should see:
   `"Congratulations!!! You ran your first container."` 

## Step 4: Inspect the Container
The application prints its message and exits quickly. To inspect a running container, try starting it in the background:
`docker run -d --name hello-app-container hello-app`

   `docker ps`
   `docker exec -it <container-id> sh`

   If the container has already exited, list all containers:

bash
`docker ps -a`
You can view its output with:

bash
`docker logs hello-app-container`
Clean up the container when finished:
`docker rm hello-app-container`

## What Happened?
Command	What it does
- docker build - Builds an image using the instructions in the Dockerfile.
- docker run	- Creates and starts a container from an image.
- docker ps	- Lists currently running containers.
- docker ps -a - 	Lists running and stopped containers.
- docker exec	- Runs a command inside a running container.
- docker logs	- Displays the output generated by a container.

## Troubleshooting

- docker: command not found	= Install Docker and confirm that it is available in your terminal.
- Docker daemon is not running	= Start Docker Desktop or the Docker service.
- The build fails at the COPY step =	Confirm that you are running docker build from inside the cloned repository folder.
- No container appears in docker ps = The application may have already exited. Use docker ps -a to view stopped containers.
- docker exec fails	= The container must still be running. Start it in detached mode with docker run -d.

# Exercise 2: DevSecOps for Git
## Step 1: Use .gitignore

Goal
Prevent sensitive and unnecessary files from being tracked by Git.

A .gitignore file tells Git which files and folders should not be included in version control.

Common Files to Ignore
Typical entries include:

Common Security Files to Ignore
.env
.env.*
*.pem
*.key
id_rsa
terraform.tfstate
.terraform/
node_modules/
dist/

Never commit passwords, API keys, private keys, cloud credentials, or Terraform state files to a repository.

**Add .gitignore: **

`.env`
`git status`

⚠️ .gitignore does NOT protect secrets already committed.

## Step 2: Use native pre-commit hooks
What This Is
A pre-commit hook is a script located at:

.git/hooks/pre-commit
Git executes it automatically before every commit.  Here we can detect secrets and block it before it's committed.


## Step 3: Use Repository and History Scanning

Create a custom rules file - `custom-rules.toml`

```
[[rules]]
id = "generic-password"
description = "Detect any PASSWORD assignment"
regex = '''(?i)password\s*=\s*["'][^"']+["']'''
tags = ["password", "custom"]
```

Run the gitleaks command

`gitleaks detect --config custom-rules.toml`
